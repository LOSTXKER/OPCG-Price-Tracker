## 1. ภาพรวม: เว็บเราแข็งตรงไหน อ่อนตรงไหน

**แข็งแล้ว (ไม่ต้องรื้อ):** มี robots.txt + sitemap อัตโนมัติจาก DB · มีระบบ JSON-LD (structured data) ครบเครื่องใช้อยู่ ~28 หน้า · หน้าเว็บส่วนใหญ่ render ฝั่ง server (Google เห็นเนื้อหา) · มี guide 7 หน้าเป็นฐาน content อยู่แล้ว · มี FAQ + FAQ schema บนหน้าแรก/guide/pricing

**อ่อน 5 เรื่องใหญ่ (เรียงตามผลกระทบ):**

1. **ภาษาสลับข้าง** — title/description ของแทบทุกหน้าเป็น**อังกฤษ** แต่ตัวหน้าเว็บที่ Google เห็นเป็น**ไทย** → คนไทยค้น "ราคาการ์ดวันพีซ" แล้ว Google โชว์ snippet อังกฤษ ไม่ match คำค้นเลย
2. **หน้าการ์ดรายใบ (หน้าเยอะสุดในเว็บ ~5,000 URL) render เป็นอังกฤษล้วน** — ชื่อไทย/ข้อความไทยมีใน DB แต่ไม่เคยไปถึง Google และไม่มีข้อความอธิบายสักประโยค (ตัวเลขล้วน = thin content) แถมมี section ข้อมูลปลอม ("Sample sale history") ติดอยู่ใน HTML
3. **H1 ไม่มีคีย์เวิร์ด** — หน้าแรก H1 จริงถูกซ่อน (sr-only), หน้าชุด H1 = "OP01" เฉยๆ ไม่มีชื่อชุด, หลายหน้า H1 generic ("ชุดการ์ด", "แพ็กเกจ", "สี")
4. **หน้าเครื่องมือ/ค้นหา Google เห็นเป็นหน้าว่าง** — ผลค้นหา, ตาราง trending, drop calculator, deck calculator โหลดด้วย JS ฝั่ง client → HTML แรกแทบไม่มีเนื้อหา
5. **ขยะหลุดเข้า index ได้** — /proto/** (หน้า mock ราคาปลอม) ไม่มี noindex, canonical รั่วจาก layout ราก (บางหน้าประกาศตัวว่า "ฉันคือหน้าแรก"), redirect เก่าเป็นแบบชั่วคราว (307) ไม่ส่งต่อพลัง link

**Insight จากวิจัยตลาด (สำคัญมาก):**
- คนไทยสะกด 2 แบบ: "การ์ดวันพี**ซ**" และ "การ์ดวันพี**ช**" (Shopee/สื่อใช้ พีช) → ต้อง cover ทั้งคู่ (แบบหนึ่งใน title อีกแบบใน H1/description)
- รูปแบบค้นจริง = **ไทยผสมโค้ดอังกฤษ**: "การ์ดวันพีซ OP01 ราคา", "SEC คือ", "OP05-119 ราคา" — คำว่า "OPTCG" ล้วนๆ มีแต่สายฮาร์ดคอร์ใช้
- คู่แข่งไทยตรงตัวมีรายเดียว: **card2price.com** (ยึดคำ "เช็คราคา" แต่ไม่มีหน้ารายชุด, ราคา community ไม่ใช่ตลาดจริง) → ชนะได้ด้วยหน้า set + ราคากลางจริง
- ช่องว่างเนื้อหาไทยที่**ไม่มีใครทำเลย**: ① rarity คืออะไร (SR/SEC/ALT) ② อัตราออกต่อกล่อง ③ วิธีดูการ์ดแท้/ปลอม ④ การ์ดโปรโมได้จากไหน ⑤ หน้ารายชุด "OPxx ราคาทุกใบ"
- โมเดลที่พิสูจน์แล้วว่า rank (PriceCharting ติดอันดับแม้ในผลค้นไทย): โครง 3 ชั้น **hub ราคา → หน้าชุด → หน้าการ์ด** + หน้าชุด render ตารางราคาทุกใบใน HTML

## 2. โครง Pillar ของเรา (3 ชั้น × 2 เสา)

```
เสาที่ 1 — เสาราคา (money pages)
  หน้าแรก  = Pillar "เช็คราคาการ์ดวันพีซ"
    └─ /opcg/sets/[code]   = Cluster รายชุด "ราคาการ์ด OP01 ทุกใบ"   ← หน้ารบหลัก
         └─ /opcg/cards/[code] = Long-tail รายใบ "OP01-003 ราคา"      ← ปริมาณเยอะสุด

เสาที่ 2 — เสาความรู้ (content pages)
  /guide  = Pillar "คู่มือ One Piece Card Game"
    └─ guide ย่อย 6 หน้า + หน้าใหม่อุดช่องว่าง (แท้/ปลอม, การ์ดแพงสุด, ร้านค้า)
         └─ ทุกหน้า link ลงไปหาหน้าชุด/หน้าการ์ด (ดันเสาที่ 1)
```

กติกากลาง 4 ข้อ (ใช้ทุกหน้า):
- **Title สูตร**: วลีไทย + entity อังกฤษ เช่น "ราคาการ์ดวันพีซ OP01 ทุกใบ — Romance Dawn | Meecard" (≤ ~60 ตัวอักษร ส่วนที่โชว์)
- **H1 เดียว มองเห็นได้ มีคีย์เวิร์ด** — ห้ามซ่อน (sr-only) ห้ามใช้คำลอยๆ ("สี", "แพ็กเกจ")
- **ทุกหน้า data ต้องมี "ข้อความจริง"** ≥ 2–3 ประโยค + FAQ — ตัวเลขล้วนๆ = หน้า thin, Google ไม่ให้ rank
- **เนื้อหาสำคัญต้องอยู่ใน HTML แรก** (server render) — ของที่โหลดด้วย JS ทีหลัง Google เห็นช้า/ไม่เห็น

| Description | อังกฤษ | ไทย: ราคากลางจาก Yuyu-tei · กราฟย้อนหลัง · PSA 10 · พอร์ตสะสม (สะกด "วันพีช" ในนี้ 1 ครั้ง) |

### 3.2 หน้าชุด `/opcg/sets/[code]` — หน้ารบหลัก (สำคัญสุดในแผนนี้)

ผู้ใช้เราเลือกจากชุดก่อนเสมอ + คำค้น "OPxx ราคา" ยังไม่มีเว็บไทยทำหน้าแบบนี้เลย = ชนะได้ทันที

- **Title**: "ราคาการ์ดวันพีซ {CODE} {ชื่อชุด} ทุกใบ อัปเดตทุกวัน | Meecard"
- **H1**: "{CODE} — {ชื่อชุด}" (ตอนนี้ H1 = โค้ดเปล่าๆ ชื่อชุดไม่อยู่ใน heading เลย)
- **เพิ่มย่อหน้าเปิด** (auto-generate จากข้อมูลที่มีอยู่แล้ว — ไม่ต้องเขียนมือ): วันวางขาย · จำนวนการ์ด · แยกตาม rarity · การ์ดแพงสุด + ราคาปัจจุบัน
- **เอาตารางอัตราออก (drop rate) ออกมาโชว์ใน HTML** — ตอนนี้ซ่อนใน dialog ที่ Google ไม่เห็น ทั้งที่เป็นข้อมูลที่คู่แข่งไม่มี + link ไป drop-calculator ของชุดนั้น
- **FAQ ท้ายหน้า** (auto จาก data): "กล่อง {CODE} มีกี่ซอง กี่ใบ" / "การ์ดแพงสุดในชุดคือใบไหน" / "วางขายเมื่อไหร่"
- **Meta description ใส่ราคาจริง**: "การ์ด {N} ใบ · ใบแพงสุด {ชื่อ} ฿{ราคา} · อัปเดตวันนี้" — ตัวเลขสดใน snippet ช่วย CTR
- หัวข้อ rarity (h2) เพิ่มคำไทยกำกับ + link ไป /guide/rarities
- ชื่อการ์ดในตารางต้อง render ชื่อไทย (มีใน DB แล้ว ไม่เคยถูกใช้)

### 3.3 หน้าการ์ดรายใบ `/opcg/cards/[code]` — long-tail หลายพัน URL

- **แก้ภาษา (ใหญ่สุด)**: ตอนนี้ Google เห็นหน้านี้เป็นอังกฤษล้วน — ต้อง render ไทยเป็นค่าเริ่มต้น: ชื่อไทย, ข้อความ effect ไทย, ชื่อชุดไทย (ข้อมูลมีใน DB แล้ว)
- **Title**: "ราคา {CODE} {ชื่อการ์ด} ({rarity}) — {ชุด} | Meecard" — โค้ดการ์ดต้องอยู่ใน title + H1 (คำค้น intent สูงสุดคือโค้ด แต่ตอนนี้ H1 มีแค่ชื่อ)
- **H1**: "{ชื่อการ์ด} {CODE}" — แก้ปัญหาการ์ด parallel หลายใบ H1 ซ้ำกันด้วย
- **เพิ่มย่อหน้าเปิด 2–3 ประโยค** (auto ต่อใบ): ชื่อไทย+อังกฤษ, โค้ด, rarity, ชุด, ราคาปัจจุบัน ฿, เปลี่ยนแปลง 30 วัน, แหล่งข้อมูล+วันที่อัปเดต → ทุกหน้ามีข้อความ unique ทันทีโดยไม่ต้องเขียนมือ
- **ลบ section ข้อมูลปลอม** ("Sample sale history", "Sample Meecard listings") → แทนด้วย**ตารางประวัติราคาจริง** (สูง-ต่ำ-เฉลี่ย 7/30/90 วัน) — ข้อมูลมีอยู่แล้ว แค่ยังไม่ render เป็นตาราง
- **FAQ ต่อใบ** (auto): "การ์ด {ชื่อ} ราคาเท่าไหร่" / "ราคามาจากไหน อัปเดตบ่อยแค่ไหน" / "Raw กับ PSA 10 ต่างกันยังไง"
- Meta description แบบ template: "{ชื่อ} · {CODE} · {rarity} · {ชุด} ราคาล่าสุด ฿X (¥Y) อัปเดตวันนี้"
- โครงสร้างข้อมูล (JSON-LD): เปลี่ยนราคาเป็น THB (ตอนนี้ JPY), เลิกอ้าง "มีของพร้อมขาย" ตอน marketplace ปิดอยู่
- เทคนิค: เปลี่ยนเป็น cache รายชั่วโมง (ตอนนี้ทุกครั้งที่ Google เข้า = query DB สด + **เขียน viewCount ลง DB**) — บอทเข้าเป็นพันหน้า/วัน ทั้งช้าทั้งปั่นยอดวิว

### 3.5 หน้าเครื่องมือ — เปลี่ยน "หน้าว่าง" เป็นหน้า rank ได้

- **`/opcg/trending`**: ตารางหลักไม่อยู่ใน HTML แรก (Google เห็นหน้าว่าง) → render ตาราง default ฝั่ง server + แยก 3 ช่วงเป็น H2 (24 ชม. / 7 วัน / 30 วัน) + ประโยคสรุปอัตโนมัติ "วันนี้ {ชื่อ} ขึ้นแรงสุด +X%" · Title ไทย
- **`/opcg/search`**: ผลค้นหาไม่เคยอยู่ใน HTML (แม้มี ?q=) → render ผลฝั่ง server เมื่อมีคำค้น + H1 โชว์จริงเป็นไทย + ใส่ลิงก์ browse (ชุดล่าสุด/คำค้นยอดนิยม) แทน state ว่าง
- **`/opcg/drop-calculator`**: โอกาสทอง — คำ "อัตราออกการ์ดวันพีซ" **ไม่มีเนื้อหาไทยเลยทั้ง Google** → เพิ่มบทอธิบายใต้เครื่องมือ (กล่องละ 24 ซอง, การันตี rarity, โอกาส SEC ต่อกล่อง — ตัวเลขมีในโค้ดแล้ว) + FAQ + Title "คำนวณโอกาสออกการ์ดวันพีซ (Drop Rate) ต่อซอง/กล่อง/คาตัน"
- **`/opcg/deck-calculator`**: หน้านี้ Google เห็น**ว่างเปล่าจริงๆ** (ติด auth gate ทั้งที่มี preview mock ที่เป็น static) → render preview เป็นค่าเริ่มต้น + FAQ กฎเด็ค (เด็ค 50 ใบ + Leader / ซ้ำได้ 4) + Title ไทย
- **`/opcg/market-overview`**: render ดีแล้ว ขาดข้อความ → เพิ่มย่อหน้า "ราคามาจากไหน คำนวณยังไง" (บล็อก methodology สร้างความเชื่อถือ) + ประโยคสรุปอัตโนมัติจากข้อมูล + Title ไทย

### 3.6 บล็อก `/blog` — เครื่องยนต์เนื้อหาระยะยาว

- Title/description ไทย + ย่อหน้าเปิด · หมวด 4 หมวดที่มีอยู่ = คลังคีย์เวิร์ดพร้อมใช้ (วิเคราะห์ตลาด / รีวิวชุด / เทคนิค / ข่าว)

### 3.7 หน้าประกอบ (pricing / about / contact / honey / raffle)

- ทั้งหมด: title/description เปลี่ยนเป็นไทย (ตอนนี้อังกฤษหมด ทั้งที่ตัวหน้าเป็นไทย)

### 3.8 สุขอนามัย index (ทำครั้งเดียวจบ — กันโป๊ะ)

1. **`/proto/**` — ด่วนสุด**: หน้า mock ราคาปลอม 11 หน้า index ได้เต็มๆ ใต้แบรนด์ → ใส่ noindex ที่ layout + เพิ่มใน robots (หรือลบทิ้ง)
2. **Canonical รั่วจาก layout ราก**: ย้าย canonical "/" จาก layout ราก ไปไว้ที่หน้าแรกโดยตรง — ตอนนี้ /guide, /opcg/decks, /saved ฯลฯ ประกาศตัวเป็น "หน้าแรก" (บอก Google ว่าเป็นหน้าซ้ำ)
3. **Redirect เก่า 307 → 308 (ถาวร)**: /cards/x → /opcg/cards/x ตอนนี้เป็นชั่วคราว ไม่ส่งต่อพลังลิงก์
4. robots เพิ่ม: /saved, /orders, /seller/, /proto/, /ref/ · ส่วนหน้า private ที่โดนทั้ง robots-block + noindex พร้อมกัน (portfolio/watchlist/login) เลือกทางเดียว: **เอาออกจาก robots แล้วใช้ noindex** (โดน block = Google ไม่มีวันเห็น noindex)
5. หน้าโปรไฟล์: title ซ้ำ "| Meecard | Meecard" (บั๊ก template) + /profile ถูก robots block ขวาง canonical ไป /@handle
6. **สมัคร Google Search Console + ใส่ verification** — ตอนนี้ไม่มี = ตาบอด ไม่รู้ว่า index ไปกี่หน้า
7. **เช็ค env โดเมนบน Vercel** (`NEXT_PUBLIC_APP_URL`) — ถ้าไม่ได้ตั้ง canonical/sitemap ทั้งเว็บจะชี้ไป meecard.app ที่ไม่ใช่โดเมนจริง
8. ภาษา EN/JP: อยู่หลัง cookie = Google ไม่มีวันเห็น — **ยอมรับเป็นเว็บไทย-first ไปก่อน** (ตัดสินใจ explicit) · ถ้าอนาคตอยากได้ทราฟฟิก EN/JP ต้องแยก URL /en/... (งานระดับสถาปัตยกรรม ไว้ตอนสร้างเว็บจริง)

## 5. ลำดับลงมือ (เรียงตาม ผลลัพธ์/แรง)

- **P0 — สุขอนามัย + meta ไทย (เร็ว ผลทันที)**: proto noindex · canonical · 308 · Search Console · เช็คโดเมน env · เขียน title/description ไทยใหม่ ~20 หน้า (ตามสูตรข้อ 3) · เพิ่มหน้าที่ตกหล่นเข้า sitemap
- **P1 — หน้ารบ (การ์ด+ชุด)**: render ไทยบนหน้าการ์ด · H1/title สูตรใหม่ · ย่อหน้าเปิด auto + FAQ auto ทั้งหน้าชุดและหน้าการ์ด · ลบ section ปลอม → ตารางประวัติราคาจริง · โชว์ drop rate บนหน้าชุด · แก้ cache/viewCount
- **P2 — เครื่องมือ + guide**: server-render trending/search/deck-calc · เนื้อ drop-calculator · retitle guide ทุกหน้า + ขยาย guide/buying + FAQ
- **P3 — หน้าใหม่**: การ์ดแพงสุด (live) → แท้/ปลอม → ร้านค้า → ตัวละคร · เดินเครื่องบล็อกตาม template

### เกณฑ์ "เสร็จ" (acceptance)
1. ทุกหน้า public: title+description ภาษาไทย มีคีย์เวิร์ดเป้า, H1 เดียวมองเห็นได้และมีคีย์เวิร์ด, ครอบทั้งสะกด พีซ/พีช อย่างละจุด
2. หน้าการ์ด: ดู view-source แล้วเห็น ชื่อไทย + ย่อหน้าเปิด + FAQ + ตารางประวัติราคา (ไม่มีคำว่า "Sample")
3. หน้าชุด: view-source เห็นชื่อชุดใน H1 + ย่อหน้าเปิด + ตาราง drop rate + FAQ
4. trending/search/deck-calc: ปิด JS แล้วยังเห็นเนื้อหาหลัก
5. /proto ทุกหน้า: มี noindex · ไม่มีหน้าไหน canonical ชี้ "/" นอกจากหน้าแรก · redirect เก่าเป็น 308
6. Search Console ยืนยันแล้ว + submit sitemap แล้ว

> หมายเหตุ: repo นี้เป็น prototype — สเปกในไฟล์นี้เขียนแบบไม่ผูกโค้ด ตอน dev สร้างเว็บจริงให้ยกเกณฑ์ acceptance ชุดนี้ไปใช้ได้เลย โดยเฉพาะข้อ 2–4 (เนื้อหาต้องอยู่ใน HTML แรกเสมอ)
